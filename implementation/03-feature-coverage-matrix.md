Read [TEST-EVIDENCE.md](TEST-EVIDENCE.md) for the latest exact executed suite counts, failures/skips, source digest, dates and tested versions. [Integration results](evidence/integration-results.json) and [browser results](evidence/browser-results.json) are machine evidence for their recorded run only. Naming a test file below does not assert its current execution passed, map every proposed TC ID to a passing test, or claim final UAT. Older evidence must not be used to claim a later source change passed.

The remaining-code column tracks safe implementation work. **BLOCKED_EXTERNAL** applies only to the separate dependency column; it does not excuse missing code. [FEATURE-GAPS.md](FEATURE-GAPS.md) gives the feature boundaries, and [EXTERNAL-DEPENDENCIES.md](EXTERNAL-DEPENDENCIES.md) names external owners/evidence. Local simulator payment never establishes a real merchant/provider relationship.

## Operational ownership and review boundary

The portal now contains an explicit agency booking queue and a separate agency-plus-finance exception/refund panel. A customer payment receipt can say `paid_pending_confirmation`; only an authorized agency action with reason and request key confirms the booking. Refund `requested` and `approved` are operational decisions. Neither state proves processor success or transfers money; no public refund-proof route exists. Support shared messages and private staff notes have separate projections. Partner review atomically creates an approved organization and membership, while invitation acceptance and commercial contracts remain unfinished.

Module implementers own source and regression coverage; QA owns executed evidence; the product owner owns scope/UAT; security/privacy reviewers own independent ACL/data acceptance. Finance/legal/provider reviewers own actual payment/refund eligibility, agency/supplier operators own real inventory and fulfillment, and native/creative reviewers own translation and brand acceptance. No human/vendor approval is inferred from local tests. Partner direct staff activation is an agency action, not a completed invitation-acceptance workflow.

The theme `functions.php` had a whole-file parse gap and was read directly; excluded deployment tooling was checked as local source rather than treated as graph evidence. This is path/scope verification, not an exhaustive security or production-readiness audit. Final execution and release evidence remain in TEST-EVIDENCE.md and the root release reports.
