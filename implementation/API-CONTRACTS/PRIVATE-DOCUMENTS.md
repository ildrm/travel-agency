# Private documents

Uploads are disabled until `ATLAS_PRIVATE_FILE_ROOT` and `ATLAS_PRIVATE_FILE_KEY` are configured. Use an isolated directory with mode `0700`, outside every directory served by WordPress or its host web server. The key is a separately managed base64 string for exactly 32 random bytes. Back up encrypted files and the database together, and keep the encryption key under separate recovery controls. The local fixture generates an ephemeral key for fictional bytes.

An agency operator drafts a purpose policy with both language notices, allowed object types, retention days, policy expiry and privacy and legal evidence references. A different authorized account approves the policy. Sensitive collection is additionally off unless `ATLAS_SENSITIVE_DOCUMENTS_ENABLED` is explicitly enabled. Sensitive documents remain scoped to the authorized object owner and agency accounts explicitly granted `atlas_manage_sensitive_documents`. Configure sensitive collection only with reviewed ownership, access and retention appropriate to the context. At present the built-in object contexts are a booking and a supported private record. Procurement supplies its own award scope resolver.

Under `agency/v1`, `POST /private-files` accepts an authenticated `multipart/form-data` request with `document`, `context_type`, `context_ref`, `policy_id` and `consent=1`. Formats are PDF, PNG and JPEG, with a 5 MiB size limit and image dimension checks. The server derives media type and the object owner, generates a UUID and verifies the policy before accepting bytes. `GET /private-files` accepts the exact context type and reference. It returns metadata with `Cache-Control: private, no-store` after scope validation.

`POST /private-files/{id}/scan` sends decrypted bytes to a trusted local scanner only after authority and quarantine checks. Configure `ATLAS_CLAMSCAN_BINARY` as an absolute executable path to a maintained ClamAV installation. A trusted extension can instead provide `atlas_private_file_scan` with `state`, `engine`, `reference` and `scanned_digest` bound to the exact content. Unavailable or mismatched evidence leaves the file inaccessible. The normal download is an authenticated, nonce-protected attachment with a generated filename. It verifies authenticated encryption and the stored content digest. It adds no public media entry or URL.

`POST /private-files/{id}/request_erasure` records an owner's request. Agency operations `legal_hold` and `purge` require the current revision and a reason. Purge requires elapsed retention and no active hold. If file deletion fails after committing the inaccessible tombstone, operations must recover and verify physical deletion in the configured directory. Backups follow their separately approved retention schedule.

Consumers such as procurement call `Atlas_Private_Files::clean_reference()` to bind the exact file UUID and digest to the same authorized object under a current approved policy. Every download checks current object authority again. A revoked policy blocks new attachment use. Stored historical records obey their established retention rules.
