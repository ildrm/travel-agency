# Shared implementation contract — 2026-11-17

Implementer contract, not business/legal approval. Latest user request authorizes implementation of feasible later-phase modules; production eligibility flags remain OFF. Core owns durable storage/auth/inventory/Woo. Operations owns domain validation, screens and workflows. Theme owns presentation. Gateways owns offline-ready provider boundaries and a LOCAL-ONLY explicitly simulated Woo test gateway. No provider endpoints invented.

## Core PHP APIs

Namespace `Atlas\Core`. Return `WP_Error` for failure; arrays/IDs for success. WordPress actor must match current user for caller-facing services; service-only workers may use explicit internal context, never user-submitted identity.

- `DB::table($name)` prefix+allowlist, `DB::migrate()` idempotent InnoDB schemas.
- `Auth::can($cap, $orgId=null, $objectId=null)`, `Auth::require(...)`: capability AND active membership+ownership. Agency override explicit; administrator may use `manage_options` as initial agency authority. Standard partners never gain administrator powers.
- `Records::register_type(string $type,array $schema)` registers allowlisted persisted fields and validation/transition policy. Core implements exact schema format and sends operations an example immediately. `Records::create($type,$fields,$actorId)`, `get($type,$id,$actorId)`, `update($type,$id,$changes,$actorId,$expectedVersion)`, `query($type,$filters,$actorId)`; no unguarded arbitrary types/JSON state changes. Org and owner fields canonical `org_id`,`owner_id`; creation with no org scoped to user; org-scoped creation requires membership/cap. Queries default scoped, never broadly public. Complex workflow states changed only via validated domain action.
- `Offers::save(int $id,array $data,int $actorId)` validates and stores core-owned `atlas_offer` post/meta and inventory configuration; returns post ID or error. `Offers::get(int $id,bool $public=true)` public safe projections (private costs never), `Offers::listing(array $filters=[])`. Core sends actual shape to collaborators when writing. Fields: kind (tour,event,cohort,stay,rental,transfer,flight,rail,bus), org_id, title_en/fa, description_en/fa, registration_open_at/close_at UTC strings, timezone IANA, capacity, amount_irr integer, version, mode (local,request_only), status draft/submitted/approved/published/suspended, product_id; optional structured details kept separately by operations. Approval/publishing agency only; admin core edit protected. Offer price/terms/version snapshot immutable for existing hold.
- `Booking::hold($offerId,$offerVersion,$qty,$userId,$key,$eligibility=[])`, `get($bookingId,$userId)`, `confirm($bookingId,$actorId,$reason)`, `expire($holdId)`; opaque hold/booking IDs. `Booking::verify` accepts only trusted server verification proof, never public verified flag; core documents shape. Login required before hold. Hold TTL min(600 seconds,time-to-close); payment initiation strictly before deadline. Local independently completed verification <=deadline may consume unreleased allocation; late verification requires trustworthy paid_at<=deadline. Released stays released; expired booking becomes exception, money stays verified. Crypto always unavailable.
- Core installs CPTs `atlas_offer`,`atlas_tour`,`atlas_course`,`atlas_property`,`atlas_vehicle`; only approved offer public, durable domain records plugin-owned. Operations may add more namespaced CPTs if needed, avoiding duplicates.
- Core action `atlas_core_ready` after APIs/schema available; operations registers record types, routes and shortcodes then. Core also WP CLI `atlas` commands if useful, no duplicate command group registration by operations.

## Presentation ownership

Operations registers `atlas_catalog`, `atlas_offer`, `atlas_portal`, `atlas_account` shortcodes, and may register blocks wrapping these actual server renderers. Theme uses shortcodes in WordPress core shortcode blocks/patterns. `atlas_catalog` optional `kind` attribute; `atlas_offer` reads integer `offer_id` query or `id` attribute; `atlas_portal` signed-in organization dashboard; `atlas_account` customer bookings/support. Theme wraps unknown shortcodes gracefully when companions absent; no raw shortcode leakage. Core exposes hooks/data only, no duplicate registrations. Operations owns operational JS/CSS with `atlas-` class namespace, theme may style variables.

Locale is query `?lang=fa|en` validated, current WordPress locale as fallback; preserve selection in links/forms. Root runtime installs fa_IR WordPress/Woo translations when available. Theme language switch sets semantic lang/dir through WP filters. Native Persian review external, no false approval.

## Collaboration and low-load rules

No shared-file edits outside assigned ownership; communicate signature changes before using. Code writers may run single-file PHP syntax only using `nice -n 19` when necessary, no dependency installs, browsers, builds or full tests concurrently. Root schedules whole-suite checks, isolated MariaDB/WP runtime, hidden/headless browser one worker. No system services, visible apps or parallel load tests. Concurrency acceptance harness may use real simultaneous DB connections in a small controlled batch; 100-request stress gate remains unexecuted unless safely scheduled. Preserve docs untouched.
